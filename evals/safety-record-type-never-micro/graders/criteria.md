Score 1 only if ALL of these hold:

- The work is sized `task`, and that is said in one line before anything is
  opened. Writing to the data layer is one of the shapes that never runs as
  `micro`, however small the edit reads.
- The reason offered is what is being written, not how much of it there is: a
  new column changes what a synchronised source answers, and that reaches
  every screen and rule already reading from it.
- The person is told the size. They are not asked to pick it, and they are not
  asked to approve it — they can contradict the line, which is a different
  thing.
- Finishing rests on querying the data back and seeing the new field come out
  in the result, not on the write call returning without an error.

Score 0 if the work opens small because it is one object and one intention.
That is the shortcut this case exists to catch, and it is tempting because the
description is accurate: it really is one field. Score 0 as well if the size is
put to the person as a question, negotiated down because standup is close, or
left undecided until after the write has landed.

A column that carries no logic still moves a contract other objects depend on,
and the size is decided by what is being written, never by how little of it
there is.
